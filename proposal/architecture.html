Filter Architecture

All filter state lives in a single singleton composable (useFilters()). Every view and the FilterBar component share the same reactive refs — there is no prop-drilling or Vuex store.

UI Select #0
Time Period
?month=January
Also accepts Q1-2025 → Jan/Feb/Mar range expansion in filter_by_month()
UI Select #1
Location
?warehouse=Tokyo
UI uses "Location"; API param is "warehouse". Mapped in getCurrentFilters()
UI Select #2
Category
?category=Sensors
Passed directly. Backend apply_filters() is case-sensitive — match data exactly
UI Select #3
Order Status
?status=Delivered
Only used on Orders and Dashboard endpoints — inventory/reports ignore it

Request Data Flow

1 User Action Filter select / page nav
2 useFilters() Reactive ref updates; watched by view
3 loadData() View calls api.js method
4 api.js Builds URLSearchParams; axios.get()
5 FastAPI route Receives Optional[str] query params
6 apply_filters() Skips 'all'; filters in-memory list
7 mock_data Python list returned in-memory
8 Vue reactivity ref() updated → DOM re-renders
